# 测试计划与发布验收

> 这是验收标准与测试设计，不是已执行的报告。所有通过状态应由实际运行结果填写。

## 1. 测试层次

| 层次 | 核心目标 |
| --- | --- |
| 规则单元 | 牌型识别、比较、万能牌、余牌和最后一手 |
| 状态机单元 | 轮次、补牌、胜利优先级、积分 |
| 属性与模糊测试 | 牌守恒、枚举完整性、无非法状态和 panic |
| 房间与协议集成 | 身份、并发、隔离、幂等、重连 |
| 模拟对局 | 全人数/模式终止性和不变量 |
| 前端及浏览器 E2E | 页面、操作、动画恢复、移动端 |
| 安全与压力 | 恶意输入、队列边界、连接恢复、资源回收 |
| 部署冒烟 | 构建产物、HTTPS/WSS、重启与回滚验证 |

## 4. 轮次与补牌测试

| ID | 场景 | 预期 |
| --- | --- | --- |
| G-01 | 2～5 人发牌 | 首出 6 张，其余 5 张，牌堆分别 43/38/33/28 张 |
| G-02 | 每种人数的连续 N−1 次不出 | 只在阈值达到时结束轮次 |
| G-03 | 连续不出后有人接牌 | passCount 清零，最后出牌者更新 |
| G-04 | 同轮之前不出的玩家后来可以接牌 | 允许 |
| G-05 | 经典 4 人，B 最后出牌 | 按 B、C、D、A 各摸 1 张，B 领出 |
| G-06 | 极速 4 人，B 最后出牌 | 仅 B 摸 1 张，B 领出 |
| G-07 | 经典模式剩余牌不足人数 | 按顺序摸完，未轮到者不补 |
| G-08 | 两种模式牌堆均为空 | 不补牌，不回收牌，继续领出 |
| G-09 | 任何模式领出/跟牌合法清空手牌 | 立即结算，之后不补牌 |
| G-10 | 游戏结束后继续 play/pass | 拒绝，不重复结算 |
| G-11 | 三人局余牌 3、5 | 获胜者 +8，其他 −3、−5 |
| G-12 | 再来一局 | 重新洗牌、清空本局状态、保留房间累计积分 |
| G-13 | 初始或摸牌后首次持有双王 | 仅本人收到提醒 |
| G-14 | 重连后同一双王通知 | noticeId 去重，不重复弹窗 |
| G-15 | 合法手牌的领出阶段 | 总存在至少一个合法动作 |

每个测试确认服务端固定行动方向；新轮清除上一轮待接牌型，不能错误要求新轮首出者继续压制旧牌。

## 5. 属性测试与枚举验证

- `ResolvePatterns` 返回的逻辑牌型均由所选物理牌恰好组成；普通点数不改变、王数量不超库存。
- `CanBeat` 严格比较：任何牌型不能压制自身同等大小；普通牌型只允许相同种类、相同长度且大一级或 2 的例外；炸弹比较满足反对称性及炸弹内部传递性。
- `GenerateLegalMoves` 每个候选均通过同一 `ValidatePlay`。
- 使用小手牌（如 1～12 张）的穷举选牌和逻辑解释作为参考，比较优化枚举的逻辑动作集合；花色等价候选可规范化。
- 合法出牌后的非空手牌不会落入禁止余牌集合；合法非空手牌在领出时存在合法动作。
- 随机/模糊输入不得引起 panic、越界访问或未授权状态修改。
- 牌守恒：54 个物理 ID 始终互斥地分布在牌堆、各玩家手牌、已打出牌集合；每次出牌/补牌都能验证。
- 任意合法正常结束的对局恰有一名空手牌玩家，且总积分变化为零。
- 固定随机种子复现发牌和动作选择；生产不使用测试随机源。

## 6. 全量模拟对局

建议发布门槛为至少 10,000 局：8 种组合，每组至少 1,250 局。可以在 CI 快速阶段减少数量，但发布验收需完成全量。

| 人数 | 经典 | 极速 |
| --- | ---: | ---: |
| 2 | 1,250 | 1,250 |
| 3 | 1,250 | 1,250 |
| 4 | 1,250 | 1,250 |
| 5 | 1,250 | 1,250 |
| 合计 | 5,000 | 5,000 |

模拟策略至少包含随机合法动作与基础启发式策略，覆盖大量主动不出、炸弹争夺、特殊牌组合和牌堆耗尽。模拟器使用真实规则和状态机，不另写简化游戏。记录每局种子、模式、人数、动作数、轮数、赢家、牌堆是否耗尽及异常原因。

终止判定可使用物理牌数量约束：成功出牌次数不超过 54；每次成功出牌后连续不出最多 N−1 次。模拟总动作上限可保守设为 54×N（最多 270；内部发牌/补牌事件不计玩家动作）。任何超过上限、无合法领出、无效结算、重复牌、丢牌或非法余牌都应使测试失败，而非强行终止对局使报告通过。

## 7. 联机、并发与安全

| ID | 场景 | 预期 |
| --- | --- | --- |
| N-01 | 创建和加入 2～5 人房间 | 房间容量、模式、席位正确 |
| N-02 | 非房主开始/重复开局 | 拒绝 |
| N-03 | 伪造他人 playerId、房间号或会话 | 拒绝 |
| N-04 | 同一动作重复 requestId | 仅执行一次 |
| N-05 | 同一 requestId 不同内容 | 拒绝 |
| N-06 | 旧 gameId / revision | 拒绝并恢复最新快照 |
| N-07 | 多客户端同时提交 | 仅当前合法动作成功，无竞态 |
| N-08 | A/B 各自的状态与事件检查 | 无对方手牌、牌堆顺序或私密提醒 |
| N-09 | 摸牌广播 | 他人只知道数量，不知道牌面 |
| N-10 | 断线、刷新、手机切后台后重连 | 恢复相同席位和最新手牌 |
| N-11 | 新连接替换旧连接 | 旧连接无法操作；旧关闭不影响新连接 |
| N-12 | 发送非法 JSON、超长消息、非法 ID | 拒绝或断开，不崩溃 |
| N-13 | 慢客户端不读取消息 | 不阻塞房间；可重连恢复 |
| N-14 | 多房间并行开局、退出及回收 | 无串房、数据竞争、goroutine 泄漏 |
| N-15 | 全员离线回收/进程重启 | 明确无法恢复，不伪造胜负 |
| N-16 | 非法 Origin、凭证过期、暴力加入 | 安全拒绝或限速 |

使用 `go test -race` 检查并发；压力测试记录硬件、连接数、房间数、CPU、内存、消息时延分布、异常率及稳定性。不要凭架构设计直接宣称某个并发容量。

## 8. 浏览器与设备 E2E

测试首页、创建/加入切换、各人数布局、两种模式、选牌、万能牌多义选择、余牌拒绝、补牌动画、牌堆耗尽、结束结算及再来一局。使用多个独立浏览器上下文模拟联机，不共享同一会话凭证。

至少覆盖桌面 Chromium 和移动端横屏视口，例如 844×390、932×430 CSS px，并验证短屏、竖屏回退和安全区。Android、iPhone/iPad 真机若未运行，应单独标为未验证；模拟视口不能替代真机测试。

## 9. 可选 AI 测试

若首发包含 AI，则执行 [AI.md](AI.md) 中的公平性、合法动作、超时回退、对照策略、并发及取消测试。改变真实隐藏状态但保持 AI 可见输入及策略种子不变，输出必须一致。报告真实对照赛数据，不把合法性测试等同于高水平策略证明。

## 10. 建议检查命令

以下为目标项目应提供的命令示例，实际以实现后的 Makefile 和 package.json 为准：

```bash
cd server
go test ./...
go test -race ./...
go vet ./...
```

```bash
cd web
npm ci
npm run typecheck
npm run test
npm run build
```

项目根目录建议提供 `make test`、`make simulate`、`make e2e`、`make build`。模拟命令应可指定局数和种子。没有对应脚本时不得假装命令已存在或通过。

## 11. 发布门禁与报告模板
