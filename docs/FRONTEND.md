# 前端界面与交互设计

## 1. 目标

采用简洁、温和的桌游风格，优先保障牌桌可用性、出牌反馈和手机横屏操作。当前文件描述功能与交互约束，不绑定尚未制作的视觉参考图。不要在界面中额外加入未要求的功能。

技术栈：Vue 3 + TypeScript + Vite + Pinia；SVG/静态图片展示牌面，CSS Transform 与 Web Animations API 实现轻量动画。公共逻辑与 PC、移动端布局分离。

## 2. 页面结构

| 页面 | 必需内容 |
| --- | --- |
| 首页 | 游戏名称、创建房间、加入房间、规则入口；可选 AI 快速开始仅在 AI 实现后出现 |
| 创建/加入弹窗 | 顶部创建/加入切换；昵称、人数/模式或 6 位房间号；单一主操作按钮 |
| 房间 | 房间号及复制、玩家席位、玩法、房主状态、开始及退出按钮 |
| 牌桌 | 自己的手牌、其他玩家席位及余牌数、当前待接牌、牌堆数量、轮次、操作栏 |
| 结算 | 获胜玩家、各玩家剩余牌数、本局积分、累计积分、再来一局/返回 |
| 规则弹窗 | 正式玩法 V1.3 的简明说明；不展示路线图中的未来模式 |

创建弹窗只提供人数和经典/极速选择，不开放未确认的规则开关。模式说明清晰：
- 经典：每轮结束所有玩家各摸一张。
- 极速：每轮结束仅最后成功出牌者摸一张。
- 两种模式均在任意玩家合法出完时立即结束。

未实现 AI 时不展示添加 AI 和快速开始按钮，不提供虚假的占位操作。

## 3. 桌面端布局

```text
┌─────────────────────────────────────────────────────┐
│ 房间号 / 玩法             牌堆数量       规则 / 网络 │
│                                                     │
│              [对手席位 / 余牌数]                     │
│ [其他对手席位]         当前待接牌        [其他对手]   │
│                        轮次与出牌者                  │
│                                                     │
│                         状态提示                    │
│              [提示]    [不出]    [出牌]              │
│                                                     │
│                 自己的手牌（可选牌）                 │
│                  昵称 / 分数 / 余牌                 │
└─────────────────────────────────────────────────────┘
```

根据人数调整其他玩家席位位置，保证自身始终在下方。2 人对家、3 人上方左右、4 人上/左/右、5 人上方两席和左右各一席；具体位置可由视觉方案微调，但席位行动方向和标记必须明确。当前行动玩家高亮，待接牌区突出逻辑牌型；出牌、过牌状态不遮挡操作区域。

## 4. 移动端布局

移动端采用独立横屏牌桌布局，而不是简单缩小桌面端。适配短屏和安全区：

- 手牌区固定在可操作区域下部，牌面重叠显示并可横向滚动；大量手牌时允许压缩间距，但确保可选中单张。
- 自己手牌、出牌按钮和待接牌区域优先；对手区展示昵称、余牌数和行动状态，压缩非必要信息。
- 短屏避免整页滚动和操作按钮被系统安全区遮挡。
- 竖屏可用响应式紧凑布局，用户旋转设备后自然切换；不调用屏幕旋转权限，不用阻断式旋转提示。
- 手机浏览器考虑 `100dvh`、安全区 inset、软键盘弹出和后台恢复。
- 触控目标建议至少 44 CSS px；复杂牌型选择可用底部浮层，不覆盖关键手牌。
- 避免把 CSS hover 作为唯一提示方式。选中状态使用抬升、描边或位置变化，不仅依赖颜色。

`room/game` store 持有服务端快照；`connection` 管理连接状态、重连、pending 请求。选中牌、动画和弹窗属于本地 UI 状态，不能反向改变权威游戏状态。PC 和移动端共享 store、通信、牌型选择、手牌组件和操作语义。

## 6. 选牌与出牌

1. 点击/触摸手牌切换选中状态，选中的牌抬升。
2. 选牌变更后取消过期预览，合并短时间连续操作（建议 80～150 ms debounce），向服务端查询合法解释。
3. 无合法解释时显示明确理由，出牌按钮不可用；不出按钮在跟牌阶段仍可用。
4. 唯一合法解释时，直接使用该解释确认出牌；多个合法解释时打开选择浮层。
5. 出牌提交后暂时禁用重复提交，等待确认和最新快照。
6. 拒绝时保持有效选中牌、显示错误；若 revision 过期则同步最新手牌并要求重新确认。
7. 成功后根据新快照更新手牌、当前牌型和行动者，动画只用于展示。

领出时隐藏或禁用“不出”；非本人行动时不发送任何出牌请求。无合法动作时显示“无牌可接”，但不自动代为不出。提示功能如启用，应由服务端的 `GenerateLegalMoves` 提供受限的合法建议（可扩展私有 `hint` 请求）；未实现提示时不展示按钮。不要在前端重复写一套完整规则。

### 6.1 万能牌多义选择

例如选中 4、5、王，领出阶段：

```text
选择出牌方式
┌──────────────────────────┐
│ 3  4  5     王 → 3       │
│ 4  5  6     王 → 6       │
└──────────────────────────┘
```

每个选项包含逻辑牌型、大小/起点以及王的替代点数。点击选项后确认或直接提交明确声明。跟在 345 后只匹配 456 时不额外弹窗。若同一组牌可以同时构成顺子和炸弹，且两种都合法，也需要选择。相同逻辑解释不因大小王位置互换产生重复选项。

### 6.2 特殊牌提示

按服务端错误码展示短提示：

| 场景 | 文案 |
| --- | --- |
| 将只剩单 2 或对 2 | 不能仅剩单张 2 或对 2，请先处理手中的 2。 |
| 将只剩王或双王 | 不能仅剩王，请搭配其他手牌使用。 |
| 将只剩 2＋王 | 不能仅剩等效对 2，请调整组合。 |
| 单 2/对 2 收尾 | 单张 2 或对 2 不能作为最后一手。 |
| 接牌错误 | 需要同牌型、同张数且恰好大一级的牌，或合法炸弹。 |
| 双王提醒 | 你同时持有大小王。双王不能直接出牌，请合理搭配其他手牌。 |

双王提示只来自本人私有消息/快照，不使用公共播报、不显示在他人玩家卡片上；每局一次，重连按 noticeId 去重。错误提示不遮挡手牌或自动清除玩家选择。

## 7. 手牌、牌型及动画

- 排序：按逻辑点数及固定花色顺序排列，2 和王置于高点数区域；大小王视觉不同、规则等价。
- 打出的物理王牌可加小标记显示“当作 6”等实际声明，公开牌型以服务端逻辑牌型为准。
- 对手只展示余牌数或背面牌，不持有其隐藏数据。
- 发牌、摸牌、出牌、炸弹、轮次切换使用轻量动画；不引入重型粒子或 3D 引擎。
- 经典模式展示全员补牌数量，极速只显示最后出牌者补牌。只有自己能看到摸入的牌面。
- 牌堆为空时保持“0”，不虚构补牌动画。
- 胜利快照到达即进入结束状态，停止任何新操作；结算弹窗可等短动画完成，但不得延迟权威状态。
- 网络重连时允许直接跳过过期动画并恢复最新快照；支持 `prefers-reduced-motion`。

## 8. 连接异常体验

状态区分连接中、已连接、重连中和会话失效。重连期间禁用游戏操作，保留牌桌内容作为待同步展示；认证成功后整体替换快照，不重复执行旧请求。若房间已被回收、服务重启或凭证失效，提示本局无法恢复并返回首页，不伪造结算。

手机切后台再返回时主动检查连接；普通页面刷新应能恢复当前席位。旧标签页被新连接替换时显示明确提示，停止自动抢占连接。

## 9. 视觉及可访问性要求

采用明确层级、有限色板、足够对比度和简洁按钮，不使用赌博、现金、充值视觉元素。牌面点数与花色在小屏可辨，玩家状态不只靠颜色表达。输入框、弹窗和关键按钮支持键盘及可读名称。所有用户昵称用文本渲染。

## 10. 前端验收

覆盖 2～5 人、经典/极速、万能牌唯一/多义解释、剩余特殊牌拒绝、双王私密提醒、牌堆耗尽、结算、手机后台与刷新重连。PC 和手机横屏分别截图验收，记录浏览器及真机测试状态。视觉效果不能替代服务端协议与规则测试。
