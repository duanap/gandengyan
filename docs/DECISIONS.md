# 规则基线与工程决策

本文件区分用户已明确的定制规则和前期方案中的实现默认值。默认值可用于直接开发，但不得将其冒充用户另行确认的规则；变更用户已确定的规则必须先取得明确授权。

## 1. 已明确的规则（锁定）

| ID | 决策 |
| --- | --- |
| R01 | 2～5 人，一副 54 张牌，首出玩家 6 张，其余 5 张 |
| R02 | 经典模式每轮所有人补 1 张；极速模式仅最后成功出牌者补 1 张；该玩家领出下一轮 |
| R03 | 牌堆摸完后停止补牌，第一名合法出完即游戏结束 |
| R04 | 跟牌允许不出；普通牌型接牌大一级，单 2、对 2 是特殊牌 |
| R05 | 顺子最少 3 张，最小 345、最大三张 QKA；同长度恰好大一级；A 不连 2，2 不连 3 |
| R06 | 大小王等价万能牌，不能单出，双王不能当炸弹；首出时允许选择王的顺子解释 |
| R07 | 炸弹三至六张，按张数先后比较，不要求大一级；同点数自然炸弹与赖子炸弹等价 |
| R08 | 出牌前禁止仅剩单 2、对 2、单王、双王或等效对 2；允许三张及以上 2 炸弹；不采用事后移交牌权 |
| R09 | 持有双王时，仅本人收到提醒 |
| R10 | 当前不实现首名出完后继续游戏的一人失败、两人失败模式，仅记录未来计划 |

## 2. 沿用前期方案的执行默认值

这些默认值构成当前设计的可执行基线；若后续用户提出不同要求，优先更新规则和相应测试。

| ID | 默认值 | 理由/注意事项 |
| --- | --- | --- |
| D01 | 逆时针行动；首局随机首家，后续同房间由上一局赢家领出 | 与已有设计一致 |
| D02 | 连对至少两对；不含 2；同长度且大一级接牌 | 已有牌型总览中的约定 |
| D03 | 单 2、对 2 可跨级压制对应普通单/对，但不能作为最后一手；任何合法炸弹可压制普通牌型 | 已有特殊牌规则 |
| D04 | 领出必须出牌；跟牌不出只消耗本次行动，后续可再次跟牌 | 避免任意空轮次 |
| D05 | 经典补牌从最后出牌者开始按行动方向执行；牌不足时按顺序发完 | 明确牌堆不足时的处理 |
| D06 | 按剩余牌数量计分，零和；不设额外倍数 | 简洁积分机制 |
| D07 | 双王提醒每局首次触发一次，重连可恢复未展示提醒 | 不重复打扰 |
| D08 | 房间 6 位数字，创建时选择目标人数、模式；房主在席位满足条件后开始 | 简洁房间管理；不自动开局 |
| D09 | PC 与手机横屏统一牌桌组件，按视口调整尺寸与间距，不调用旋转权限 | V1.4 视觉调整 |
| D10 | 所有正式规则只有一个服务端实现；内存房间、JSON WebSocket、Go 单体服务 | 便于部署和维护 |
| D11 | 首发以真人联机为基本范围；AI 设计随包提供，明确纳入任务时才实现 | 避免把建议扩展误当成已确认的强制需求 |
| D12 | 房间内累计积分；服务器重启默认不恢复未完成牌局和临时积分 | 内存方案的明确边界；历史持久化按需扩展 |

## 3. 网络与房间层默认值（可调整配置）

- 目标人数为 2～5，满目标席位且都在线时房主可开始。游戏中不允许新玩家进入既有席位，只允许合法会话重连。
- 房间创建与加入通过 HTTP 获得身份凭证；WebSocket 首条认证消息确认身份。房间号不是凭证。
- 暂不设置强制出牌倒计时、自动代打、强制弃权或中途加入规则。掉线时保留席位；非行动者掉线不阻断其他合法操作；轮到掉线者时等待其恢复。
- 游戏进行中关闭页面或离开仅视为断开连接，不自动判负、不更改游戏规则。房主可以在等待/结算状态管理房间；若明确提供“结束房间”管理功能，取消未完成对局需与正常结算区分，不产生胜负积分。
- 全员离线的空闲房间可按运营配置回收（建议 30 分钟，正常在线对局不受此限制）。这是资源回收，不是游戏流局规则。
- 生产环境只接受可信 Origin 和安全连接；断线重连采用短期会话凭证，重连替换旧连接。服务器重启后旧会话可能失效，应明确提示。

## 4. 当前不做

未明确要求的账号系统、排行榜、数据库、在线聊天、观战、回放、真钱支付、AI 训练、跨服务器迁移，以及多赢家/一人失败/两人失败玩法均不是本期正式要求。可以在后续独立需求中评估；不提前增加 UI、协议枚举或结算分支。
