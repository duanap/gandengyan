# 开发实施计划与交付标准

## 1. 任务边界

当前版本仅实现 V1.3 规则、经典/极速模式、2～5 人联机、PC/移动端界面、重连和结算。AI 作为独立可选模块；未来胜负模式仅见路线图。以下里程碑按依赖顺序推进，不是已经完成的事项。

## 2. 里程碑

| 阶段 | 主要任务 | 阶段验收 |
| --- | --- | --- |
| M0 规则锁定 | 阅读规则与决策，建立仓库目录、版本和测试约定 | 规则冲突全部澄清或按明确默认值记录 |
| M1 规则引擎 | 物理牌、牌型识别、万能牌、比较、余牌检查、合法动作枚举 | R/S 系列规则测试全部通过；穷举参考比对通过 |
| M2 游戏引擎 | 洗牌发牌、行动/轮次、两种补牌策略、获胜与结算 | G 系列测试通过、牌守恒、零和 |
| M3 模拟器 | 随机与启发式动作、固定种子、统计与失败复现 | 全人数及模式至少 10,000 局，规则状态无异常 |
| M4 房间与协议 | 创建/加入、串行队列、权限、快照、幂等、重连 | N 系列集成测试及 race 检查通过 |
| M5 前端 | 首页、房间、牌桌、万能牌选择、私密提醒、结算 | 桌面及移动端完整流程，类型检查和构建通过 |
| M6 AI（可选） | 合法动作、手牌规划、有限搜索、公平视图 | AI 专项测试通过，对照赛真实记录 |
| M7 系统验收 | 多浏览器联机、弱网、安全、资源回收与压测 | 关键 E2E、协议隔离、并发安全及压力报告 |
| M8 构建与部署准备 | Go Embed、Makefile、Nginx/systemd 模板、发布回滚说明 | 可重复构建与本地部署冒烟通过 |
| M9 正式发布（另行授权） | 维护排空、备份、发布、线上验证 | 真实版本及线上测试记录、明确未验证项 |

M3 的模拟器可先使用测试策略，不依赖生产 AI。M6 未纳入开发时跳过，不影响其他正式规则的验收；前端不得暴露相应不可用功能。

## 3. 阶段实现要点

### M1：先做可测试的规则核心

- 建立物理牌 ID 与逻辑点数编码。
- 写规则测试后实现 `ResolvePatterns`、`CanBeat`、`ValidateRemaining`、`ValidatePlay`、`GenerateLegalMoves`。
- 重点测试同长度顺子、三至六炸等价比较、多义万能牌、非法余牌和收尾。
- 不使用 UI 或 WebSocket 证明规则正确性。

### M2–M3：先完成无网络整局

- 构建独立可注入随机源的状态机；每个动作作为原子提交。
- 经典/极速仅在补牌策略上分支。
- 验证首位玩家合法出完时立即终止；牌堆为空不补牌。
- 每次模拟动作检查牌守恒、余牌合法、轮次阈值、结算唯一。
- 失败种子纳入可复现回归；禁止添加流局或移交领出权掩盖问题。

### M4：接入联机

- 实现房间目录、六位房间号、会话身份、房主权限。
- 将全部游戏命令送入单房间串行队列。
- 实现玩家专属 DTO 和状态快照；防止隐藏字段泄露。
- 增加请求去重、revision、重连替换、回收机制与协议测试。

### M5：实现可用界面

- 先建立类型、网络层、store，再分别构建 PC 与移动布局。
- 按服务端合法预览处理万能牌选择，不在客户端自行裁决。
- 使用简洁桌游风格和轻量动画；禁止通过动画回调改变规则。
- 真机/模拟测试区分记录；不增加未来模式设置。

### M6：可选 AI

- 独立可见视图输入；只通过房间正常动作路径操作。
- 优先启发式高质量基线，再按需要增加有限采样搜索。
- 以真实测试衡量胜率、时延和公平性，不宣称无证据的最优策略。

### M7–M8：可部署交付

- 运行全量测试、并发检测、端到端流程、构建和压力检查。
- 编写部署脚本/配置和运维说明，保证没有数据库或 Docker 的强制依赖。
- 明确重启会影响未完成内存牌局，不宣称无损发布。

## 4. 交付物

| 类别 | 交付 |
| --- | --- |
| 源码 | Go 后端、Vue 前端、公共协议类型 |
| 文档 | README、规则说明、架构、协议、部署和路线图 |
| 工具 | 本地开发命令、构建脚本、模拟器、测试脚本 |
| 测试 | 单测、回归测试、集成、E2E 及模拟结果 |
| 部署 | Go 可执行产物构建方式、Nginx 与 systemd 配置 |
| 验收记录 | 实际命令、结果、版本、已知限制和未验证事项 |

## 5. 完成定义

- 所有当前正式规则完整实现，无临时替代逻辑。
- 支持所有人数 × 模式组合；合法出牌、补牌、结算和重连可正常运行。
- 无隐藏信息泄露、重复结算、跨房间状态污染或规则死循环。
- 前后端构建成功，测试结果可复现，开发与部署文档可用。
- 未纳入首发的 AI 及未来玩法明确不适用，不提供无功能按钮。
- 不将未测试或未部署事项描述为已完成。

## 6. 最终报告格式

1. 本次实现范围与未纳入范围。
2. 核心文件及架构变化。
3. 实际运行的测试和构建命令、通过/失败/未执行状态。
4. 模拟对局覆盖数量及种子/失败复现方式。
5. 本地启动与生产构建/部署方法。
6. 已知限制、待确认事项及后续建议。

如任务未授权生产发布，最终结果应为源码及本地验收交付，而不是擅自部署线上服务。
